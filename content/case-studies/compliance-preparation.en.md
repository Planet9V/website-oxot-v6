# Compliance preparation: evidence from work already underway

A composite case, illustrating one of the seven engagements OXOT is regularly asked to run — not a single identifiable operator. The pattern is real and recurs across sectors; the audit and the regulator are not disclosed.

```keyfacts
Scope :: sites, business units or regions
Basis :: risk-based, IEC 62443 lifecycle, mapped to the applicable regime
How we work :: evidence built into work already running
Output :: an audit-ready trail, not a parallel exercise
Measure :: reportable risk reduction, not controls implemented
```

## The situation

A statutory deadline was approaching — the specific regime varies by jurisdiction, from NIS2 in Europe to sector-specific critical-infrastructure reporting rules in the US and Australia, but the shape recurs with any regulation on a fixed clock — and the operator's instinct, encouraged by more than one vendor, was to stand up a dedicated compliance project alongside the security work already underway. Two workstreams, two sets of documentation, two teams that would eventually have to reconcile what each had found. The security programme was already producing exactly the kind of evidence a regulator would ask for; it had simply never been organised to say so.

## What OXOT did

The existing OT security programme's own lifecycle, already run against IEC 62443, was mapped directly onto the regulation's specific requirements rather than duplicated to satisfy them separately. Where the programme's risk assessments, segmentation work and incident-response planning already produced the evidence a regulator would need, that evidence was formatted and indexed to the regulation's own clauses. Where a genuine gap existed — a requirement the security programme had not yet reached, on its own risk-based schedule — that gap was named explicitly and given its own sequencing, rather than folded silently into the existing plan and quietly missed.

## The output

An audit-ready trail assembled from work the operator was already funding, not a second budget line for a parallel project that would have produced a second, disconnected set of documents. The measure the board saw was the one it already tracked — reportable risk reduction — with the regulatory mapping sitting alongside it as a by-product of the same work, not a competing deliverable.

## The through-line

A compliance deadline answered by a parallel project produces two things that do not agree with each other and a security team now doing the same analysis twice. A compliance deadline answered by mapping an existing, risk-based programme onto the regulation's own clauses produces one set of evidence that satisfies the regulator, the insurer and the operator's own board — because it was never manufactured for any one of them in the first place.
