# Plant architecture review & roadmap: the as-built picture, and a sequence that survived

A composite case, illustrating one of the seven engagements OXOT is regularly asked to run — not a single identifiable facility. The pattern is real and recurs across sectors; the site is not disclosed.

```keyfacts
Scope :: a site, a line or a defined zone
Runs for :: typically 2–6 weeks for the review, then a staged roadmap
Basis :: IEC 62443-3-2 + your operational risk
How we work :: passive-first, from documents you already hold
Output :: an as-built architecture + a roadmap ordered by risk removed per euro
```

## The situation

The network drawing on file was three revisions behind the plant. A firewall rule opened during a shutdown two years earlier was still open. Nobody had a single answer to which assets on the floor could reach which others, because the answer lived in three places — the original design package, a spreadsheet the previous OT engineer kept, and the actual switch configurations — and none of the three agreed with the other two. The plant manager did not need a diagram that looked correct. He needed one that was correct, and a plan for what to do about the gap that would not get vetoed the first time it collided with a production schedule.

## What OXOT did

The as-built picture came from documents already on hand — P&IDs, asset registers, prior network drawings — reconciled passively against what the network itself actually showed, rather than assumed from the design intent. No active scanning of the process network and no agent on a controller; where something could only be confirmed by testing, it happened in an agreed window with a named person able to stop it. Every finding was priced in what it would cost the line if it went wrong, not in a severity score the plant manager would have to translate before he could act on it. The roadmap that followed was sequenced by risk removed per euro, and every item on it was checked against the plant's actual maintenance calendar before it went on the list — a fix nobody can schedule around a shutdown is a fix that gets deferred indefinitely, and a roadmap that ignores that fact is a document, not a plan.

## The output

A network architecture the plant's own team could recognise as theirs, corrected rather than redrawn from a template. A prioritised risk register in the plant's own vocabulary. A staged roadmap that named the shutdown window each stage depended on, so it could be handed to the plant manager as a schedule rather than a wish list — and survived the first planning meeting, because it had already been built around the constraints that meeting would have raised.

## The through-line

A diagram that is merely accurate on the day it is drawn is out of date within a quarter. What holds is a review that reconciles the record against reality once, honestly, and a roadmap sequenced against how the plant actually runs rather than how a project plan assumes it does — because the roadmap that gets vetoed in the first planning meeting was never really a roadmap.
