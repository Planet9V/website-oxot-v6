# IEC 62443 adoption: zones and conduits as engineering practice, not paperwork

A composite case, illustrating one of the seven engagements OXOT is regularly asked to run — not a single identifiable operator. The pattern is real and recurs across sectors; the sites are not disclosed.

```keyfacts
Scope :: per zone and per asset class, applied across an estate
Basis :: IEC 62443 SL-1 / SL-2, zones and conduits per 62443-3-2
How we work :: a floor set where the smallest site can actually reach it
Output :: control checklist + evidence, not a certificate exercise
Fit :: engineering practice, revisited on every project — not annual
```

## The situation

The operator had a policy document referencing IEC 62443, produced two years earlier for an audit, filed and largely unread since. Each of the group's plants had its own answer to what "compliant" meant, because each had interpreted the same document differently and none had been asked to reconcile it against the others. A new project team would design a control system, discover the policy existed midway through commissioning, and retrofit whatever it required — expensively, and usually incompletely, because the policy had never been written with a specific project's constraints in mind.

## What OXOT did

Zones and conduits derived to IEC 62443-3-2 for the estate, and a target security level set deliberately reachable — SL-1 or SL-2, per zone and per asset class, rather than one aspirational number for the whole company that the smallest site could never actually meet. The standard was rewritten as a control checklist with the evidence each control required, so a site engineer could demonstrate the requirement was met rather than assert it in a self-certification nobody checked. Critically, the standard was built into the same design-review process every new project already went through, rather than left as a separate document a project team discovered after the fact.

## The output

A baseline every site in the group could actually reach and prove, instead of twenty plants each with a different private answer to the same question. New projects designed to the standard from the start, at the cost of a design-review line rather than a commissioning-stage retrofit. An audit trail that reflected what each site had actually done, not what a filed document asserted it should have done.

## The through-line

A standard adopted as a document is read once and revisited at the next audit. A standard adopted as engineering practice gets applied on every project because it is reachable, checked because the evidence is built in, and current because it was never allowed to become a document that sits apart from the work.
