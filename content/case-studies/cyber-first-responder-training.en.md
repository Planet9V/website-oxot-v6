# Cyber first responder training: the people on shift, trained for the first hour

A composite case, illustrating one of the seven engagements OXOT is regularly asked to run — not a single identifiable site. The pattern is real and recurs across sectors; the facility is not disclosed.

```keyfacts
Scope :: shift operators, control-room staff, plant management
Format :: tabletop exercise, position-based roles
Basis :: capability transfer, not a slide deck
Design point :: works at 3am, on a holiday, mid-shift-change
Output :: a plan the people on shift can actually run
```

## The situation

The operator had a documented incident-response plan, and it named the right people: a security lead, a small response team, an escalation path to management. It had never been tested against the shift roster. The plan assumed the named lead would be reachable and on-site — true on a Tuesday afternoon, not true at three in the morning, not true over a holiday weekend, not true during a shift change when the two people who knew the plan best were both off the floor. The gap was not in the plan's content. It was in the assumption about who would be standing in the control room when it mattered.

## What OXOT did

The exercise was built around positions, not people — the incident-response role was tied to "whoever is running the console" rather than a named individual, so the plan worked whatever the shift roster happened to be that day. A tabletop scenario, run with the actual on-shift teams rather than a headquarters response team, walked through a plausible OT incident from first alarm to escalation: what an operator would see, what a controls engineer would check, when the ICS network team got pulled in, and where the threshold sat for calling it a security event rather than an equipment fault — a threshold defined jointly with process engineering, so operators were not left guessing whether a strange reading was a fault or an attacker, and so the process-engineering severity call was baked into the plan itself rather than reinvented under pressure. Safety, process controls, operators and the OT network team ran the exercise together, deliberately including the handoff moment at shift change, since that is where institutional knowledge is most likely to fall through a gap.

## The output

An incident-response plan the people actually on shift could run, because they had already run it once, in a room, before anything was actually wrong. The exercise surfaced exactly the gaps a desk review would have missed: a shift-change handoff step nobody had written down, an escalation contact who had left the company eighteen months earlier and never been updated in the plan, an assumption that the on-call security lead's mobile number worked at the site, which it did not, because the site had no signal in the control room.

## The through-line

A response plan written for the team that wrote it is a plan for a team that may not be there. Training built around the position, tested against the actual shift roster including the awkward hours, is a plan for whoever is actually on shift when it matters — which is the only version of the plan that is ever going to run.
