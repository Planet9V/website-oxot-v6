## §6 — Pipeline stage system — EXTEND, DO NOT REPLACE

Current 7 stages: `upload → convert → classify → ner → relationships → embed → graph`

Each stage:
- Reads config from `ot_inventory.pipeline_stage_config` (model, system_prompt, temperature, max_tokens).
- Calls `setStage()` to write `artifacts.provenance_stage_runs` (lifecycle: entered → succeeded/failed).
- Emits SSE events read by `src/pages/customer/documents.tsx`.
- Uses `server/lib/pipeline-stage.ts` `setStage()` helper.

**A6 adds conditional stages AFTER classify when doc_code matches:**
```
classify → [extract_fmeca | extract_hazop | extract_rams | extract_mor | extract_risk_register | extract_critical_items] → ner → ...
```

Each new stage in `server/processes/stages/`:
- `extract-fmeca.ts` (or one `register-extract.ts` with internal switch)
- Reads doc text from `artifacts.document_provenance.text` (existing).
- Invokes `register-extractor.ts` `extractRegisters()` (existing).
- Persists to `seldon.*` (existing tables).
- Calls `setStage('extract_fmeca', 'succeeded')` (existing helper).

Zero new framework. Zero new task queue.

## §7 — Auth + middleware

**`server/auth.ts`:**
- Local fallback creds: `admin@oxot.local` (oxot_admin_2026) + `rz@oxot.local` (demorz, customer role).
- Session TTL 24h, in-memory.
- `validateCredentials()` tries Postgres `oxot_users` first; falls back to local.

**`server/lib/rls-context.ts` / `rls-tx.ts`:**
- `getOrgIdFromRequest()` → X-Organization-Id header or `req.oxot_organization_id`.
- `pgQueryScoped()` opens client + BEGIN / SET LOCAL ROLE oxot_app / set_app_context($orgId) / COMMIT.
- Admin mode bypasses RLS; `pgTxScoped()` provides atomicity.

**A4 integration:**
- New `server/lib/bloodhound-client.ts` — server-side HMAC client.
- Stores BH `TOKEN_ID` + `TOKEN_KEY` in env vars only.
- All BH calls go through OXOT server middleware → existing auth middleware authorizes the OXOT user → server then calls BH on user's behalf.
- BH credentials NEVER reach browser.
