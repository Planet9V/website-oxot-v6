## 3. Technology & Architecture

### Deployment Architecture

Device42 consists of three primary components [[53]](https://docs.device42.com/auto-discovery/remote-collector-rc/) [[54]](https://docs.device42.com/getstarted/deploy-device42/) [[56]](https://docs.device42.com/getstarted/installation/resource-and-deployment-architecture-overview/):

**Main Appliance (MA)**: Linux-based central management platform providing:
- CMDB repository and data persistence
- Web interface (HTTPS, Port 443)
- Appliance manager interface (Port 4343 for admin access)
- SSH console access (Port 404)
- Webhook and API endpoints for third-party integrations
- Reporting engine (Exago-based, replaced in recent versions)

**Remote Collectors (RC)**: Lightweight Linux virtual appliances deployed in customer environments for:
- Distributed discovery execution (eliminates need to open multiple ports to MA)
- Local discovery job processing with result aggregation
- Support for unlimited remote collectors per MA [[53]](https://docs.device42.com/auto-discovery/remote-collector-rc/)
- Websocket-based communication with MA (no inbound Port 443 requirement per modern architecture) [[57]](https://www.device42.com/blog/2017/10/09/capacity-planning-for-digital-transformations-and-experimental-support-for-power-monitoring-with-remote-collectors-in-v14-0-0/)
- Time Series Database (TSDB) for power and performance metrics collection [[57]](https://www.device42.com/blog/2017/10/09/capacity-planning-for-digital-transformations-and-experimental-support-for-power-monitoring-with-remote-collectors-in-v14-0-0/)

**Windows Discovery Service (WDS)**: Windows-specific discovery component for:
- WMI-based discovery of Windows systems
- Active Directory credential management
- Windows-only protocols and APIs
- Deployment on customer Windows servers or dedicated Windows VMs
