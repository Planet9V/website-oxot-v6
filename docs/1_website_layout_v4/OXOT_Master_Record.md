## Review history — 3 independent rounds, and why that mattered

| Round | Model | Billing | What it found |
|---|---|---|---|
| 1 | Sonnet (via `ruflo agent_execute`) | **OpenRouter — later found to be a billing mistake**, ~$0.20 real spend | 5 of 8 "needs rework," established the baseline grading rubric (OXOT-Specificity / Spec Compliance / Accessibility / Buildability) |
| 2 | Opus (native `Agent` tool) | Claude Max subscription, $0 external | Cross-checked round 1 — 6/8 verdicts agreed; caught 3 new defects (self-contradictory scroll direction, a row/column wording contradiction, wrong ARIA role) |
| 3 | Fable 5 (native `Agent` tool) | Claude Max subscription, $0 external | **Verified the fixes, not the originals** — found 6 of 8 prior "fixes" were incomplete or cosmetic, not actually resolving the flagged issue |

**The methodology lesson, worth keeping:** round 3 is where the real value was. Grading original text catches obvious problems; grading *whether a stated fix actually fixes it* catches the much more common failure mode — a fix that changes the words without changing the mechanism (Zone Sequencer: dropped the "IEC 62443" label, kept the zone-sealing visual grammar; Evidence Dossier: fixed the flip's timing, not the flip). Any future review pass on this system should default to a third "verify the fix" round, not stop after round 2.

## Two items previously open here — both resolved 2026-08-24

**Decision Ledger's "NOW" status color token — RESOLVED.** The Foundation Spec's 6 tokens didn't include anything meaning "committed/active" — NOW previously borrowed amber ("proposed/pending"), a mismatch every review round flagged and no fix actually resolved. Owner decision: NOW reuses `--signal-blue` (a genuine semantic fit via its existing "active route/communications" meaning), not an invented 7th token. See `OXOT_Visual_Foundation_Spec.md` §3.1.

**Light-mode signal contrast — RESOLVED.** Independently discovered during the `stage_1_opus` comparison pass: 5 of 6 signal colors failed WCAG 1.4.11's 3:1 non-text minimum against `--paper-50` (verified by direct computation, not estimate — cyan measured as low as 1.65:1). This blocked the Foundation Spec's own Phase-1 approval gate. Owner decision: OKLCH-based `-on-light`/`-on-dark` per-theme token pairs, hue held constant, lightness adjusted per surface and re-equalized across all six in each theme. See `OXOT_Visual_Foundation_Spec.md` §3.1 and `stage_1_opus/comparison_vs_existing_system.md` §3.2 for the original finding.

## Governance and hard rules in effect (all discovered/set 2026-08-24)

- **Max 4 concurrent agents** — after a 5-agent swarm died to a real API 529 outage with zero output. [`feedback_max_4_concurrent_agents.md`]
- **No OpenRouter text billing** — `ruflo agent_execute` silently falls back to OpenRouter when `ANTHROPIC_API_KEY` is absent (confirmed absent, container-side, twice). Use the native `Agent` tool instead — it runs on Claude Max, not a separate bill. Image generation via OpenRouter remains a separate, sanctioned exception. [`feedback_no_openrouter_text_billing.md`]
- **RuFlo's Recall gate now genuinely cycles** — fixed a bug where Recall only fired once per session instead of once per Recall→Persist cycle, deployed to all 3 hook copies, verified live.
- **`claude-mem` is running somewhere on this Mac** (the `claude-mem-postgres` container, ~82M tokens/$14.30 in 24h on a shared OpenRouter key) despite being permanently banned in this project — not this project's usage, but flagged and not yet resolved. Owner's call whether to stop that container.

**Where a split or merge wasn't obvious, the reasoning:**

- **Decisions split 3 + 1.** "Can We Change Safely?" is the only one of the four that is a *comparison of two system states* — that is literally Baseline vs Virtual Control (Deliverable 3), which pattern 2 *is*, not merely serves. The other three are register entries — prioritise (NOW), fund (spend), accept (NEVER) — which is one Decision Ledger, not three different patterns.
- **Assurance merged to one row.** All five topics share both the Assurance Composition Rule and pattern 5 verbatim; there is no per-standard variation in structure, only in content.
- **Industries merged to one row, with a warning.** Same rule, same pattern — but the pattern is explicitly "a renderer, not a design," and the standing project rule is that similar pages must not reuse one section template. Same row here means same *rule*, not same *layout*.
- **Resources split four ways.** The Resources rule covers one visual family but four genuinely different content types (card index, term list, case-file index, technical documents); pattern 8's scope was deliberately narrowed to "Case Studies primarily" in review round 3, so stretching it across all of them is the exact structural gap that narrowing was meant to close.
- **An unresolved tension worth naming:** `OXOT_Layout_Styles.md` restricts Evidence Dossier Panel to "Assurance's alone," while its own "How patterns combine" section puts it on a Platform-type page "where technical, not sales-dashboard." This matrix follows the restriction, which is why Product Sheet / Technical Specification are marked "needs pattern decision" rather than quietly borrowing pattern 5. That contradiction should be settled in `OXOT_Layout_Styles.md`, not here.
